# v1.0.0 review - 19 October 2026

Scope: branding, first-run setup, Hebrew by default, optional Arabic.
Method: research references, inspect each lens, fix a specific failure, rerun its acceptance check, inspect screenshots, score again. Scores below are self-assessments, not independent testing or user ratings.

## Reference products

- [Wispr Flow setup](https://docs.wisprflow.ai/articles/3152211871-setup-guide): permission handling, shortcut setup and practice dictation. Lesson: first-run success means usable dictation, not just installing a model. Dibbur still lacks a guided practice dictation.
- [Superwhisper model setup](https://superwhisper.com/docs/get-started/choose-your-model): separates a recommended path from a model library and makes local-model downloads explicit. Lesson: keep model engineering out of the default path, show one-time size honestly.
- [Handy](https://github.com/cjpais/handy/): local transcription, configurable shortcut, optional cloud processing. Lesson: preserve local operation and expose advanced controls in settings, not onboarding.

## Issues found and fixed during this review

1. The first-run catalog excluded both Hebrew and Arabic Url-source models. Replaced the catalog with automatic Ivrit Turbo download and optional Lahjat Turbo.
2. Handy wordmark remained in four visible screens. Replaced with Dibbur logo; general-settings hand icon replaced with microphone. Upstream acknowledgments remain.
3. Arabic download failure left an endless progress card. Failure now shows an error and restores the button.
4. Model-selection failure only showed a transient toast. Added a persistent error and retry action.
5. A remounted screen could start a second download. Existing downloads now continue without another request.
6. Retry wording in Hebrew was unnatural. Changed to "לנסות שוב".
7. Button icon and label were visually separated. Centered them together and added keyboard-focus feedback.
8. Download progress had no accessible semantics. Added progressbar labeling and live status.
9. Verification displayed 0% after transfer. It now shows 100% while verifying.
10. Permission and migration copy still called the product Handy. Updated these product labels, preserving upstream attribution elsewhere.

## Release gates and honest limits

- Browser simulation is evidence for UI and frontend state logic, not native app execution.
- Automated Mac builds validate compilation and packaging, not microphone permissions, shortcut capture, transcription accuracy or paste into other apps.
- The application remains unsigned/unnotarized. Gatekeeper friction remains; do not call this a frictionless consumer install.
- No "WOW", "best product", native-runtime pass or perfect score is claimed.
- The release can address the reported onboarding defects while the whole-product QA score remains limited by untested native behavior.
